# Switch from Chat to Work

Accept a suggested handoff when a Chat request needs execution tools.

Applies to: Both

## Why a handoff appears

Chat can suggest Work when a request requires browser interaction, executing code, or creating files. The suggestion explains the reason and does not itself execute the task.


## Review the choice

Use Switch to Work to accept the handoff. If you only need an explanation or code example, stay in Chat. Work still requires the normal permissions and approvals.


## Temporary conversation considerations

Temporary mode is available only in Chat. Treat a switch to Work as a change in the persistence model; Work uses a saved conversation and workspace.


## What the confirmation contains

The dialog is titled Continue this in Work? It shows the reason and identifies whether the request needs a browser, code workspace, or file workspace. Stay in Chat dismisses the offer. Switch to Work accepts it and starts the Work flow after confirmation; merely seeing the dialog does not authorize execution.

Your request and recent conversation carry over. This is useful for turning a researched idea into a deliverable, but it is not a promise that every historical message will be copied verbatim. Restate critical constraints if they are far back in a long thread, particularly filenames, output requirements, or decisions that would change the task.


## Choose the right handoff for the outcome

For “Explain how this Python function works,” stay in Chat. For “Run it against these files, fix the failures, and return the corrected project,” use Work. Similarly, summarizing a public topic may need only Chat search, while filling out a form on a website needs browser interaction and any required approvals.

A handoff adds capabilities; it does not remove restrictions imposed by the instance, the website, or the provider. The Work model can be different from the Chat model because each mode has its own configured choices. Review the selected Work model and available features when the new task opens.


## Privacy, usage, and troubleshooting

If the original conversation is temporary, the dialog warns that switching creates a saved Work conversation with the context you share. Select Stay in Chat if that persistence change is unsuitable. A temporary Chat cannot become a temporary Work workspace because temporary mode is limited to Chat.

Work can incur provider and runtime usage according to the edition. Community reports usage without its own credit wallet; the managed service uses its cloud charging configuration. If accepting does not complete, wait for the pending request and inspect the displayed error before clicking repeatedly. If Work is unavailable, ask the instance owner or cloud operator to confirm your account permissions.

After a successful handoff, check that the new task reflects the intended request. For example, clarify whether “make this into a report” means a written response or a downloadable document. Supply any missing attachment in the saved Work conversation. Approve consequential actions only when their actual details are available; the handoff confirmation is not blanket consent for every later action.
