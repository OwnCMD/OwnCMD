# Conversation history and deletion

Find previous conversations and remove conversations you no longer need.

Applies to: Both

## Find a conversation

Use Search conversations in the sidebar. Open an existing conversation to review messages or continue the work. Temporary chats do not appear as saved history.


## Delete a conversation

Use Delete conversation and review the confirmation before proceeding. Download required output files before deleting the task.


## Scheduled conversations

Each scheduled run creates its own Work conversation. Run history can show Conversation deleted when its linked conversation has been removed. Removing a conversation is distinct from pausing or deleting its schedule.


## Organize work around conversations

Use one saved conversation for a related task and its revisions. This keeps clarifications and the associated Work output together. Search conversations when you need to return later, then read the recent messages and activity before giving a follow-up so you know the latest state.

A conversation is different from a saved memory or a schedule. Deleting a thread should not be used as the control for disabling future scheduled runs. Likewise, removing a memory is done from Memory, and clearing a website sign-in is done from the browser section of Settings. Choose the control corresponding to the data you intend to remove.


## Before deleting a Work conversation

Open generated output and download the files you need. For a multi-file application, use Export project rather than collecting only the final message. If the task is still running or awaiting input, review that state before deletion so you do not discard useful work without noticing.

Select Delete conversation and read its confirmation. Treat deletion as a destructive action: this documentation does not promise a recycle bin or an undo workflow. If the thread came from a schedule, retain any required run result separately and inspect the schedule before deciding whether it should continue creating new runs.


## When a conversation is missing

First clear or adjust the Search conversations query. Confirm that you are signed into the intended account, because task ownership is account-scoped. A temporary chat is expected to be absent from saved history and cannot be recovered by changing the search query.

A scheduled run marked Conversation deleted has lost its linked conversation; this does not mean the schedule itself was deleted. If an existing saved conversation fails to load, note the exact error and ask the operator to investigate. Avoid creating multiple duplicate tasks merely because a request is still loading. Browser refresh can reload saved state, but it cannot resurrect a discarded temporary session or an explicitly deleted conversation.

When continuing old work, supply any changed requirements explicitly. The original task may contain assumptions that were correct at the time. Ask the assistant to verify current facts again where necessary, and keep the same thread only when its previous context is still useful.
