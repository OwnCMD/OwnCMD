# Project workspace and files

Inspect, edit, and export the files generated by a Work task.

Applies to: Both

## Open Project workspace

The Project workspace provides a file explorer, editor, terminal, and preview controls for the task. File paths are relative to the project, such as src/App.jsx.


## Edit safely

Pause OwnCMD before editing while the agent is running. Save or discard unsaved changes before opening another file, closing the workspace, or stopping it. The interface prevents these transitions when edits would be lost.


## Download your work

Use Download file for an individual file or Export project for the full project. Export before removing a conversation or moving to a different installation.


## Stop a workspace

Stopping the workspace preserves saved project files. Unsaved editor changes must be saved or discarded first. Runtime processes and saved files have different lifetimes.


## A practical inspect-edit-check workflow

Pause the agent if the workspace shows that OwnCMD is working. Open Project workspace, select the relevant file in the explorer, and inspect it before editing. Choose Edit file, make the smallest change needed, and use Save file. Use Discard if you want to return to the loaded content instead.

After saving, run the relevant check in the terminal or inspect the application preview. A successful save confirms that the source was written; it does not confirm that the program compiles or behaves correctly. If you want the agent to continue, explain the manual change and the remaining task so it does not unknowingly work from an older assumption.


## File paths, tabs, and unsaved state

The explorer and file tabs help move between project files. A new file requires a relative file path such as src/App.jsx. The UI shows Unsaved when content has changed, and it blocks several navigation actions until you save or discard. This protects changes in the editor that have not yet reached the workspace.

A large file can have a truncated preview and disabled editing. Use Download file to inspect the complete file externally. Do not copy only the visible preview and overwrite the original, because that can discard content beyond the truncation point. Use the project export when file relationships and directory structure matter.


## Storage and lifecycle questions

Saved project files and running processes are separate. Stopping the workspace preserves saved project files, but a development server or interactive process may need to be started again. Closing the workspace modal is a navigation action and should not be treated as a durable backup.

The instance can impose workspace size and file-count limits. If a write or dependency installation fails, read the error and check whether generated assets or dependency directories are consuming space. Avoid repeatedly creating large duplicate exports inside the project. Download a known-good project before major changes, and keep a copy outside OwnCMD when it is important to your work.
