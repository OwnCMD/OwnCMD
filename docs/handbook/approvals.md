# Approvals and requests for input

Review consequential actions and provide missing information.

Applies to: Both

## Action approvals

A Review before continuing card presents an action that requires your confirmation. Read the stated reason, then use Approve action or Decline. Do not approve an action whose destination or consequences are unclear.


## Questions from OwnCMD

Your input is needed requests can contain individual fields, a free-text response, or optional additional details. Complete required fields and press Continue. Sensitive fields are masked and can offer Show and Hide controls.


## Prefilled answers

Saved Personal details may prefill relevant fields. Review and correct them before continuing. Prefill is a convenience, not authorization to submit information silently.


## Authentication and challenges

Some requests offer Take browser control. Use it for website login or other interactions that need a human, then return control. Website verification challenges may prevent automated progress; OwnCMD does not guarantee bypassing them.


## Review the concrete action

Before selecting Approve action, identify what is being submitted, to whom or where, and whether it matches your request. A browser task may involve preparing information before the final consequential step. Approval should be based on the actual details visible at that stage rather than a general statement that the task sounds acceptable.

Use Decline when the proposed action is incorrect. Follow up with the correction needed, such as a changed destination or amount, rather than approving and hoping the agent adjusts it. Approval UI is a control point in the workflow, not proof that the underlying form or extracted information is accurate.


## Answer structured questions accurately

Some input requests contain several labelled fields. Fill the requested fields and use Additional details only for context that does not fit them. Optional fields are marked. The input type can be email, date, number, phone, secret, or one-time code, so follow the label and purpose rather than pasting an entire paragraph into every box.

Secret fields offer Show and Hide where implemented. Masking protects the screen from casual viewing but does not make a submitted value unnecessary to the task. Prefilled fields can come from Personal details; confirm that they are current and appropriate for this particular website. Press Continue only after checking the complete set.


## When to use browser takeover

Use Take browser control when the request offers it and the step needs direct human interaction. This is often preferable to describing a changing website screen in text. Complete the visible step, then return control so the agent can resume from the resulting page.

An unanswered approval can leave the task in a waiting state. Check for an input card before assuming a compute failure. If you change the task while it is waiting, make the correction explicit. A scheduled run may also stop for input; its original scheduling consent does not imply permission to answer an unexpected website challenge or approve every new consequential action.
